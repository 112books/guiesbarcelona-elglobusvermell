1. Com funciona (sense sistema propi)

L'editor de continguts (Sveltia CMS) no té el seu propi sistema d'usuaris. Tota l'autenticació es delega a GitHub: qui té accés d'escriptura al repositori del web, pot entrar a l'editor amb el seu token personal (PAT).

Per tant, gestionar "qui pot editar" i "qui pot administrar" es fa directament a GitHub, no dins l'editor.

2. Rols: Admin vs Editor

Hi ha tres nivells d'accés al web:

Nivell Qui l'ha de tenir Què pot fer
Propietari del repositori (112books) Responsable tècnic (Joan — LinuxBCN) Tot: convidar i treure editors, canviar configuració del repositori, gestionar GitHub Actions i el desplegament.
Editor (col·laborador Write) Persones de l'equip del Globus Vermell Entrar al CMS amb el seu propi token i modificar/publicar fitxes d'edificis i pàgines. No pot gestionar altres usuaris ni tocar la configuració.
Usuari públic Qualsevol visitant del web Consultar el web. No necessita cap compte ni contrasenya.
Totes les persones que s'afegeixen com a col·laboradores reben accés Write. Amb aquest nivell ja poden editar tot el contingut via CMS. La gestió del repositori (convidar, treure, configuració) la fa sempre en Joan.

3. Si la persona no té compte de GitHub

Cal un compte de GitHub abans de poder-la convidar. És gratuït i triga un minut:

  1. Ves a github.com/signup.
  2. Registra't amb el teu correu electrònic, tria un nom d'usuari i una contrasenya.
  3. Verifica el correu (GitHub envia un codi o enllaç de confirmació).

Un cop té el compte creat, ja es pot procedir a convidar-la (secció següent). No cal cap pla de pagament ni configuració addicional.

4. Convidar algú nou

Només ho pot fer algú amb rol Admin.

  1. Ves a github.com/112books/guiesbarcelona-elglobusvermell → Settings → Collaborators.
  2. Clica Add people.
  3. Cerca pel nom d'usuari de GitHub o pel correu electrònic amb què es va registrar.
  4. Tria el rol Write (accés d'editor).
  5. Confirma la invitació.

5. Què ha de fer la persona convidada

  1. Rebrà un correu de GitHub amb la invitació (o la veurà a github.com/notifications).
  2. Ha d'acceptar-la.
  3. Un cop acceptada, ja té accés al repositori — segueix la Guia de l'editor per crear el seu propi token (PAT) i entrar al CMS.
Cada persona crea el seu propi token — mai es comparteix un token entre diverses persones.

6. Treure l'accés a algú

  1. A la mateixa pàgina de Collaborators, busca la persona a la llista.
  2. Clica els tres punts al costat del seu nom i tria Remove.
Això treu l'accés a l'instant. Si la persona tenia un token propi, deixa de funcionar immediatament — no cal fer res més.

7. Que NO fer

No comparteixis el teu token amb ningú, ni per convidar-lo ni per donar-li accés temporal. Cada persona ha de crear el seu propi.
  • No cal donar accés a cap altre nivell — n'hi ha prou amb afegir la persona a aquest repositori amb accés Write.
  • Si cal fer alguna gestió del repositori (canviar configuració, eliminar branques, etc.), ho fa sempre en Joan directament.
